La implementación principal del algoritmo se desarrollo en el lenguaje \texttt{C++}. El ejecutable tiene varios parametros para poder parametrizar el algoritmo. Estos incluyen \verb|n = INT| para el número de individuos por generación, \verb|g = INT| para el número de generaciones (iteraciones), \verb|--mut FLOAT| y \verb|--cro FLOAT| para indicar el valor de la probablidad para mutuación y cruzamiento, respectivamente, y un paramtro \verb|-i TEXT| para indicar el archivo de la instancia a leer.

Los experimentos se ejecutaron en los laboratorios del departamento de Informatica de la UTFSM, conocidos como LABCOM, conectado mediante \verb|ssh|. Estos computadores tiene sistema operativo Linux Fedora 40 (Forty), con un Inter Core i5-10500 @ 3.10 GHZ (6C, 12T), con 16 GB de memoria RAM DDR4

Las instancias poseen los datos de los clientes $c$, un conjunto de $C$ clientes que pueden ser atendidos por dron, las matrices $\tau_{ij}$ y $\tau_{ij}'$ que indican los tiempos de viaje de nodo $i$ a nodo $j$ para camión y dron, respectivamente. Se tiene los valores de $S_L$, $S_R$ y $E$ para las caracteristicas del dron, y los viajes permitidos en un conjunto $F$. Se asume que un viaje sea permitido no implica que el dron sea capaz de entregarlo por la bateria $E$.


Para la evaluación del trabajo realizado se generaron distintos tipos de parametros. Los parametros de base son dos, uno default y otro con parámetros sintonizados mediante paramILS. 
ParamILS (Parameter Iterated Local Search) se define en \cite{hutter2009paramils} como un marco de trabajo (framework) automatizado para la configuración y calibración de algoritmos. En \cite{montero2018tuners} se indica que ParamILS automatiza y sofistica el proceso manual de ajuste mediante Búsqueda Local Iterada (ILS).
Se utilizo ParamILS dado su eficiencia y recomendación entregada por el ayudante. Además se justifica su uso, dado que en \cite{montero2018tuners} se concluye que concluye que cuando el objetivo es maximizar resultados de la metaheurística, ParamILS es el método más recomendado, ya que explota intensivamente las regiones prometedoras y devuelve la mejor configuración global encontrada.

Se hicieron dos instancias de sintonización. La primera fue una instancia de una hora que retorno \verb|-n 200,-g 200, --mut 0.2 --cro 0.3|, mientras que la segunda instancia se ejecuto con más posibles valores para las variables durante 8 horas, retornando \verb|-n 200 -g 250 --mut 0.2 --cro 0.3|. Esto se guardaron como dos archivos llamados \verb|param_tuned_g200| y \verb|param_tuned_g250|, respectivamente.
El default fue una instancia inicial que se utilizo para pruebas iniciales que se mantuvo para hacer comparativas. Corresponde a \verb|-n 200 -g 200 --mut 0.3 --cro 0.3|.

El objetivo de la experimentación sera evidenciar las diferencias que se generan cuando cambia el número de individuos como cuando se cambián los parámetros del evolutivo, según tiempo y evaluación.

Adicionalmente, cada una de estas pruebas se ejecuto de dos formas distintas: Con una población general iniciada aleatoriamente mediante shuffle y otra mediante el GRASP mencionado anteriormente en la sección de Representación. Esto nos sirve para comparar la calidad de las soluciones dado una solución inicial distinta. Los datos se guardaron según si tuvieron GRASP como población inicial o no, y adicionalmente un archivo que junta ambos resultados. Dado que por cada instancia se ejecutaron $24$ parámetros distintos, dos veces según solución inicial, da un total de $960$ ejecuciones realizadas.
